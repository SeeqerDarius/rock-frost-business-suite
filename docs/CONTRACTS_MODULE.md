# Contract Management

**Status (2026-10-07):** Core release (Increment 5a). Contracts, parties, private versioned documents, version history and comparison, templates, clause library, confidentiality, numbering, settings, dashboard, register, and search are implemented. Approval workflows, obligations, milestones, renewals, amendments, termination workflow, notifications, calendar, e-signature, Accounting and Fleet integration, risk scoring rules, and reports are later increments (see "Roadmap").

## Module and entitlement

- Module key `contracts`, route prefix `/app/contracts`, permission prefix `contracts.`. It is a normal catalogue module, so platform operators can enable it, subscriptions can entitle it, and access is enforced server-side by `requireModuleAccess("contracts")` on every page and action, plus `canAccessModule` on route handlers. `actorFromTenant()` passes permissions through `hasPermission()`, so contract permissions are inert whenever the organization is not entitled.
- `publicListing: false`: Contracts is not yet marketed on public surfaces (homepage, `/modules`, public pricing, self-service signup, sitemap, login). The public module page, screenshot, and public price will be added when marketing assets exist. Setting `publicListing` to true (and adding `MODULE_SEO.contracts` and a screenshot) publishes it.
- Provisional pricing seed: GHS 449 per month, GHS 4,490 per year, 8 seats, GHS 25 per extra seat (create-once seed; operators edit it at `/app/platform/subscriptions`). The owner should confirm the commercial price before public listing.

## Permissions and roles

`contracts.view`, `contracts.create`, `contracts.update`, `contracts.delete` (archive and restore; contracts are never hard-deleted), `contracts.approve`, `contracts.terminate`, `contracts.renew` (reserved for lifecycle increments), `contracts.manage_templates`, `contracts.manage_clauses`, `contracts.view_financials`, `contracts.view_confidential`, `contracts.manage_settings`, `contracts.export`.

Seeded roles: Contract Manager (all), Contract Reviewer (view, approve, financials, export), Contract Viewer (view). Organization Owner and Admin hold all permissions. The shared Team directory at `/app/contracts/staff` manages these roles.

## Data model (migration `20261007090000_contracts_core`, additive)

`ContractSettings` (numbering format and prefix, yearly reset, expiry alert days, confidential access policy), `ContractCategory`, `ContractType`, `Contract`, `ContractParty`, `ContractDocument`, `FileContent`, `ContractVersion`, `ContractTemplate`, `ContractClause`, `ContractClauseLink`, `ContractAccessGrant`, `ContractLink` (cross-module relationships, used by the integration increment). Every table carries `organizationId`; all lookups are organization-scoped. Indexes cover organization with status, expiration, renewal, owner, counterparty, category, currency, and start date, plus a GIN index on tags. CHECK constraints guard value, date order, notice period, currency shape, version numbers, and single-target access grants.

## Behavior

- **Numbering:** `{PREFIX}/{YYYY}/{SEQ:6}` by default (for example `CTR/2026/000001`), configurable with `{PREFIX}`, `{YYYY}`, `{YY}`, `{MM}`, `{SEQ:n}`. Allocated under a per-organization advisory lock in the organization timezone, unique per organization, optional yearly reset, and skips numbers already used.
- **Versions:** creation is version 1; every change to a versioned field, and every status change, creates an append-only `ContractVersion` with a snapshot, changed fields, a change summary (long text recorded as "changed"), reason, actor, and time. Active contracts require a reason to edit. Every contract has an internal owner (the creator by default); leaving the owner blank on edit keeps the current owner. Users with permission compare any two versions field by field. Users without financial access never see financial values in details, lists, versions, or comparisons, and cannot change them.
- **Lifecycle (core):** Draft, activate (needs a start date), cancel, mark expired, archive (from draft, cancelled, expired, or terminated), and restore (to the last non-archived status). Approval, renewal, amendment, and termination workflows come with the lifecycle increment and will gate activation.
- **Parties:** multiple parties with standard roles or a custom role, legal and contact details, identifiers, signatory, primary flag, and an optional link to an Accounting contact in the same organization.
- **Documents:** private storage (`src/lib/storage/private-files.ts`): bytes in `FileContent`, never a public URL, SHA-256 checksum stored and verified on download, content-signature check against the declared type, 4 MB limit (Vercel request body cap; upload uses the `POST /api/contracts/documents` route handler because Server Actions are capped at 2 MB, with a same-origin check). Re-uploading the same type and title creates a new version that supersedes the previous one; nothing is overwritten. Removal is a recorded soft removal; the bytes are kept. `GET /api/contracts/documents/[documentId]` re-checks session, entitlement, `contracts.view`, and confidentiality, returns `no-store` attachments, and audits each download. Another organization's document returns 404.
- **Confidentiality:** standard contracts are visible to anyone with `contracts.view`. Confidential and restricted contracts are visible only to the creator, owner, and explicit grants (user, role, or HR department). `contracts.view_confidential` opens confidential contracts only when the organization enables "confidential admin access" in settings (off by default), and never opens restricted contracts. Lists filter in the database with the same rule; detail, edit, documents, and downloads report hidden contracts as not found. Viewing a confidential contract is audited. Platform operators work in their own organization context and cannot reach tenant contracts.
- **Templates:** versioned by code; one active version per code (activating retires the previous). Variables such as `{{organization.name}}`, `{{counterparty.name}}`, `{{contract.number}}`, `{{contract.startDate}}`, `{{contract.endDate}}`, `{{contract.value}}`, `{{contract.currency}}`, `{{organization.address}}` are filled at drafting; only the context's own keys render. The contract stores the rendered text and the template version; later template versions never change it. Templates can be duplicated.
- **Clause library:** versioned clauses with name, category, text, jurisdiction, language, owner, effective date, status (draft, approved, retired), and usage (recommended, required, optional, restricted). Only approved clauses attach; restricted ones need `contracts.manage_clauses`. The contract page warns when required clauses are missing.
- **Search and register:** server-side, paginated (25 per page, up to 100) search across number, title, counterparty, department, jurisdiction, tags, party names, and owner, with filters for category, owner, currency, tag, clause code, and value range (financial users). Views: all, drafts, active, expiring (90 days), expired, terminated, archived.
- **Dashboard:** real counts by status, expiring in 30/60/90 days, past expiry while active, upcoming auto-renewals, renewal decisions due, 12-month expiry trend, risk and department distribution, and (financial users) active value by currency (currencies are never summed together), by category, and top counterparties. A summary widget appears on the organization dashboard.
- **Audit:** created, viewed (confidential), updated, confidentiality changed, status changes, parties added and removed, documents uploaded, downloaded, and removed, clauses added and removed, access granted and revoked, templates and clauses created, versioned, activated, approved, and retired, and settings changes, with actor, organization, IP, and user agent.

## Roadmap

1. **Lifecycle (5b):** configurable approval workflows (value, department, type, risk, currency, jurisdiction, branch thresholds; approve, reject, request changes, comment, reassign, escalate), obligations and milestones, renewals and configurable reminders, amendments referencing the parent, controlled termination, in-app notifications, calendar views, and an e-signature provider adapter (internal acknowledgement labeled as such).
2. **Integrations and reporting (5c):** links to Accounting contacts, invoices, bills, and payments, planned billing schedules (no automatic journals), Fleet vehicles, drivers, owners, and Work and Pay agreements (relationships only), configurable risk scoring, and reports with export (register, values, expiring, renewal forecast, obligations, risk, counterparty exposure, spend and revenue, terminated, amendments, approval performance).
3. **Public listing:** marketing page, screenshot, and confirmed public price.
